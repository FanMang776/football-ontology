# 前端体验重构设计：剧情模式 + 因果链卡片 + 图谱简化 + 视觉打磨

日期：2026-10-03
状态：已与需求方对齐设计方向，待评审

## 背景与目标

现有前端五个 Tab（世界总览/事件流/球员对象/决策中心/学习路径）功能齐全，但四个体验痛点导致「不太好用」：

1. **没有叙事主线**——五 Tab 平铺，不知道先看哪个，每次打开像重新开始
2. **图谱看不懂**——节点多、边无谓词标签、实线/虚线含义不直观
3. **操作流程割裂**——「受伤 → 看建议 → 审批执行」要跨多个 Tab，上下文断裂
4. **视觉质感平淡**——能用但不精致

目标读者：**需求方自己学习 + 讲给别人听**。成功标准：打开后 5 分钟内能沿着剧情走完「事件 → 感知 → 派生 → 建议 → 治理 → 写回」的完整故事；自由探索仍然可用。

技术路线（已确认）：**现有原生 JS 骨架上重构**，不引入构建链、不换框架。图谱保留 Cytoscape 但大简化。

## 改动一：因果链卡片（后端 + 前端，最先做）

> 治「操作割裂」；事件注入后的传导报告升级为本项目核心教学点的主视觉。

### 后端：`chain` 结构化

现状：`engine/world.py` `_settle()` 返回中文字符串列表；`/api/events` 原样返回 `chain: [str]`。

改为：`_settle()` 返回结构化步骤列表 `[{stage, text}]`，`stage` 取值固定四种：

| stage | 含义 | 现有文案来源 |
|---|---|---|
| `perceive` | 感知：事件进入对象收件箱 | 「感知到比赛/训练事件…」 |
| `settle` | 结算：效果写 effects 层 | 「伤情…写入 effects 层」「痊愈…移除」 |
| `compute` | 派生：状态全量重算 | （现状无此步文案，新增一条固定文案：「体能等派生状态全量重算」） |
| `rules` | 规则：建议重算（推论） | 现状建议触发情况混在尾部文字，拆出 |

文字内容保持现有中文表述风格不变（确定性纪律：文案是代码常量，非生成）。一个事件通常产生 2–4 步，按 perceive → settle → compute → rules 顺序排列。

消费方同步修改：

- `engine/knowledge_base.py:101` 审计 detail 取 `chain[0]` → 取首个步骤的 `text`
- `scripts/explore.py:85` 打印 chain → 打印 `步骤.stage` 徽章 + `text`
- `web/app.js renderEventReport` → 见下
- `tests/test_api.py:33` 保持 `"chain" in body`，另加一条断言：chain 元素是含 `stage`/`text` 键的对象

### 前端：`renderEventReport` 重做

竖排因果链卡片，每个阶段一行：**阶段徽章（中文：感知/结算/派生/规则）+ 该步文字**。状态变化（`state_changes`）用「旧 → 新」高亮数字呈现（现有样式升级）。触发的建议渲染为可点击 chips——点击后切换到决策中心 Tab 并滚动到对应 action 卡片（复用 `switchTab`，卡片用临时高亮类标出）。未触发建议时保留现有「建议是推论，条件未过就不产生」的解释。

## 改动二：剧情模式（治「没有叙事主线」）

顶层入口：topbar 右侧「▶ 剧情模式」按钮。激活后底部出现**剧情坞**：进度点（9 个）、旁白卡片、上一步/下一步/退出按钮。剧情坞激活时 dim 其余 UI 之外不加遮罩（图谱仍可见可点）。

剧本为 `app.js` 声明式常量数组 `TOUR`，每步 `{tab, text, highlight, action}`：

- `tab`：该步自动 `switchTab()` 到的 Tab
- `text`：旁白文案（讲解这一步该看什么）
- `highlight`：要高亮的 DOM 选择器或图谱节点 id（加临时 CSS 类）
- `action`：可选的自动动作（复用现有函数），供「注入事件」「执行审批」步骤使用

九步剧本：

1. 世界总览：欢迎——灰色实线是声明的事实，青色虚线是 OWL-RL 推论（高亮图例）
2. 世界总览：点开任一球员节点，抽屉里看声明 vs 推断事实（高亮图谱）
3. 球员对象：describe() 四问——是谁/状态/为什么/能做什么
4. 事件流：注入「亚马尔受伤 4 周」事件（action 自动提交）
5. 事件流：读因果链卡片——感知→结算→派生→规则（高亮 event-report）
6. 决策中心：建议出现了——建议是推论，不是数据（高亮 actions-list）
7. 决策中心：治疗的两步审批——执行 → 待审批 → 确认（action 触发第一次执行，旁白解释 pending）
8. 决策中心：审计日志 + 执行后建议自动消失（建议=推论的闭环）
9. 学习路径：指回 learn/ 四章——每个 Tab 是一章的可视化对应物

实现约束：不新增后端端点；`action` 只调用现有 `sendEvent`/`executeOne` 等函数或直接 `post()` 已有 API。第 4 步要求世界处于初始状态，剧情启动时若检测到 `kb.tick > 0`（`/api/audit` 非空），旁白提示「建议先重置演示」并提供一键重置按钮。

## 改动三：图谱简化（治「看不懂」）

1. **预设替代裸勾选**：过滤区顶部加两个预设按钮——「核心」（默认：球员 + 俱乐部 + 类 TBox）和「完整」（全部 7 类）。勾选框保留，预设只是批量设置勾选状态。与现状的差别：Match 和 InjuryRecord 从默认视图移出（比赛/伤病是事件流里才需要看的实体）。
2. **边加谓词标签**：cytoscape 边元素携带谓词中文标签（`/api/graph` 需在 edge 数据中加 `p` 的中文映射，映射表放前端常量、API 只传谓词本名——改动最小化：`graphElements` 里把 `e.p` 存入 edge data，前端用 `PRED_ZH` 常量表渲染）。zoom < 0.6 时隐藏标签避免糊成一团（监听 `cy.on('zoom')` 切换 stylesheet 类）。
3. **类（TBox）节点视觉降级**：位置推断边（如「亚马尔 → 前腰」的 rdf:type 推论）依赖类节点存在，因此类节点**不折叠**（修正前面设计中「折叠」的说法），改为小一号、灰边框、置底层，与实例节点视觉分层。
4. 保留现有的一跳聚焦（点击 dim 其余）与空白恢复。

## 改动四：视觉打磨（治「质感不行」）

`style.css`（810 行）顶部已有部分变量，收敛为完整设计 token：色板（含语义色）、间距刻度、字体阶、圆角/阴影规范。全站卡片、面板标题层级、按钮（primary/ghost/badge）统一到 token。新增组件（剧情坞、因果链卡片）直接按 token 写。

原则：教学产品该有的干净度，不做装饰性花活。实现阶段加载 `frontend-design` 技能辅助具体视觉决策。

- 删除 `app.js` 电商残留死代码：`FOCUS_PREDS`、`focusSubgraph`、`renderFocusSubgraph`、`restoreFullGraph`（均为无调用 + 电商谓词词汇）

## 不做的事

- 不引构建链/框架（已确认）
- 不做增量推理、不改引擎六层分层
- 不加「全部执行」按钮（`/api/actions/execute-all` 后端已有但前端不接，YAGNI）
- 不动 `/api/reset` 语义、审批两步流程、fitness 公式
