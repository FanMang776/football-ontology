# 05 · 智能体面对本体世界：Agent 的工具不是 API 堆

> 配套实验：Web 端「智能体」Tab（`LLM_MODEL=mock` 时为演示模式；配好 OpenAI 兼容端点即接真实模型），以及 `tests/test_agent.py` 的脚本化假模型。

## Agent 缺的不是大脑，是一个能进去的世界

LLM 会说话。但「帮德布劳内轮休」这句话要变成世界的真实变化，中间隔着一条完整的语义链：德布劳内是谁 → 他现在状态如何 → 有没有这条建议 → 执行会改什么 → 谁允许执行。这些问题的答案不在语言里，在本体世界里。

所以二期的关键设计只有一句话：**给 Agent 的工具就是本体操作，不是一堆 REST 端点，更不是裸 SPARQL**。`engine/agent.py` 的工具表只有六个，每个都对应世界的一扇门：

| 工具 | 本体语义 |
|---|---|
| `list_players` / `describe_object` | 读世界：对象与派生状态（四问） |
| `list_suggestions` | 问推论：当前建议清单（规则层产出） |
| `preview_action` | 推演：不落库的影响预览 |
| `execute_action` | 行动：走完整治理门 |
| `inject_event` | 感知：事件入口 |

Agent 循环（`run_turn`）手写不到 40 行：模型要调工具 → 执行 → 结果喂回 → 直到模型给出文字回答，上限 6 轮。每一轮在对话里都是一张可见的工具卡片——「智能体怎么用世界」因此是可观察的，不是黑盒。

## 治理门对 Agent 一视同仁

这是二期最重要的不变量。`execute_action` 工具就是 `kb.execute`——第四章的治理三要素原样生效：

1. **前置条件**：报名满 16 人时让 Agent 征调青年队？veto 照写，建议照消失。Agent 没有特权路径。
2. **审批**：`StartTreatment` 第一次执行返回 `pending=true`，系统提示词明确要求 Agent **停下来向用户复述审批要求**，用户确认后才再次执行。两步审批防的正是「语义错 → 决策错 → 执行错」——Agent 时代这条链跑得更快，门就更要结实。
3. **审计**：Agent 的每次执行照记 `kb.audit`。事后回看「世界为什么变成这样」，人类操作和 Agent 操作在同一个日志里。

## 一个刻意的 asymmetry：事件不上治理门

细看工具表会发现：`inject_event` 不需要审批。这不是疏忽——**事件是世界的感知输入（嘴），动作才是治理对象（手）**。「亚马尔受伤了」是世界里发生的事，没人审批它；「轮休德布劳内」是主体对世界的干预，必须过门。本体建模时分清这两类写入，是治理设计的第一步。

## 建议是推论，执行时重验

Agent 读世界和执行动作之间，世界可能已经变了（另一个 Tab 注入了事件、或人类执行了动作）。没关系：`actions.execute` 本来就会用最新的建议清单二次校验，不在清单里就拒绝。「推断和派生永不落库、随事实即时重算」这条一期核心不变量，恰好是 Agent 并发安全的地基——不需要额外的锁协议，事实校验就是协议。

## 拒答纪律：世界里没有的数据就说没有

系统提示词里钉了一条：用户问「下赛季引进谁」，Agent 必须回答**世界没有这个数据**，而不是用语言模型的先验编一个。这是「有事实，才有理解」的边界——本体世界给了 Agent 一个可以查证、可以行动、也因此**可以知道自己不知道**的地方。LLM 负责理解语言，本体提供世界；世界没有的，LLM 不该替它做梦。

## 动手练

1. 在 `engine/agent.py` 的工具表里加一个新工具（比如查询规则手册 `rules_view`），体会「扩能力 = 加一行工具声明 + 一个实现」。
2. 思考：如果给 `inject_event` 也加审批门，demo 里哪条教学叙事会变味？（提示：嘴和手的区别还在吗？）
