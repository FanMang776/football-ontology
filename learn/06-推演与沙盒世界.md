# 06 · 推演与沙盒世界：执行是假的，因果链是真的

> 配套实验：Web 端「智能体」Tab 问"如果轮休德布劳内会怎样"（mock 模式即可），以及 `tests/test_simulation.py` 的脚本化钉子。

## 预览答一半，推演答整条

决策中心的"预览"（`engine/actions.py` 的 `preview`）只做一件事：调用动作的效果函数，把将要写入/移除的三元组列出来，不落库。它能告诉你"会写哪些三元组"，回答不了执行后世界如何反应——因为预览不跑重算管线。

推演（`engine/simulation.py` 的 `simulate`）回答四层问题：

| 层次 | 问题 | 预览 | 推演 |
|---|---|---|---|
| 效果层 | 会写哪些三元组？ | ✅ | ✅ 每步 message |
| 状态层 | fitness / squadStrength 变成多少？ | ❌ | ✅ `world_diff.state` |
| 建议层 | 哪些建议消失？新冒出什么？ | ❌ | ✅ `suggestions_removed/added` |
| 连锁层 | 第 2、3 步做下去，世界长什么样？ | ❌ | ✅ `steps` 列表 |

一句话定义：**推演 = 拿一份当前世界的拷贝，在里面把动作真的执行一遍（完整治理 + 全量重算 + 规则刷新），然后把沙盒世界和真实世界做 diff 讲给你听。**

## 沙盒是真世界，只是被扔掉了

`open_sandbox` 的全部秘密在一件事上：六层模型里可变的只有四层。

```python
sim = KnowledgeBase()              # declared 从 ttl 重新 parse（312 条，毫秒级）
for t in real_kb.effects:          # 效果层拷贝
    sim.effects.add(t)
for t in real_kb.retractions:      # 撤销层拷贝
    sim.retractions.add(t)
sim.params = dict(real_kb.params)  # 阈值参数拷贝（决策中心滑杆改过的也带过去）
sim.pending = set(real_kb.pending)
sim.refresh()
sim.world.bootstrap()              # 派生状态基于沙盒事实重算
```

`state` 层不用拷——它是算出来的，`bootstrap()` 会全量重写。沙盒建好之后，`execute`、审批门、前置条件、veto、审计——每一行代码都和真实世界跑的是同一个。这就是推演可信的原因：你在沙盒里看到的世界反应，就是真执行后会发生的反应，**唯一区别是没发生**。

沙盒的 audit、tick、pending 都是它自己新建的，随沙盒一起丢弃。`tests/test_simulation.py::test_simulate_leaves_real_world_untouched` 用"八个部位指纹"钉死了这一点：推演前后，真实世界的 effects / retractions / state / params / pending / tick / audit / 建议清单逐项相等。

## 审批门没开后门，是发起者已确认

治疗动作在真实世界要两步：第一次执行返回 `pending`，队医确认后才放行。推演里如果照搬，链条就断在审批上，多步连锁走不下去。

`simulate` 的处理方式是给治理叙事留的：**`execute` 零改动**，是驱动循环在收到 `pending` 时自动再调一次——动作列表是用户（经 Agent）发起的，发起即确认。但报告如实标注：

```json
{"n": 1, "action_id": "action_StartTreatment_p_st1", "ok": true,
 "pending_in_sandbox": true, "message": "已执行：…"}
```

`pending_in_sandbox: true` 的意思是"这一步在真实世界需要审批"。门没变，变的是推演的发起者已经点过头。SYSTEM_PROMPT 第 4 条纪律随之钉死：推演结果只在沙盒成立，采纳必须走 `execute_action`。

## 多步连锁：世界反应之后，再做下一个

`simulate_actions` 的参数是动作 id 列表，引擎在沙盒里顺序执行、每步之间全量重算——第 2 步的建议清单是第 1 步执行后的清单。这正是"建议是推论"的又一次兑现：轮休完某球员，治疗建议可能消失、征调建议可能冒出来，沙盒里全部即时重算。

两个边界行为，测试钉死：

- **中途条件失效续走**（`test_multi_step_chain_and_conditional_failure`）：列表里某个动作在第 1 步之后已不在建议清单中，该步 `ok=false`，后续步骤继续尝试——和真实 `execute` 的二次防护语义一致；
- **veto 传导只发生在沙盒**（`test_veto_cascade_inside_sandbox`）：报名 14→16 达上限后第三次征调被否决，veto 三元组写进沙盒的 effects，真实世界纹丝不动。

## 世界 diff：报告的最后一层

`_state_diff` 把两边 KB 的 state 图按 (主体, 谓词) 归并成 from/to：

```json
{"state": [
    {"id": "p_am1", "field": "fitness", "from": 62, "to": 82},
    {"id": "club_star", "field": "squadStrength", "from": 87, "to": 90}],
 "suggestions_removed": ["action_RestPlayer_p_am1"],
 "suggestions_added": ["action_CallUpYouth_AttackingMidfielder_p_yam1"]}
```

注意第二条：伤病不进 fitness 公式（`engine/objects.py`：fitness = 100 − 出场/训练消耗 + 轮休恢复），但伤员不计入阵容强度——所以治疗的推演结果里，变的是 `club_star` 的 `squadStrength`，不是伤员的 fitness。**世界 diff 会如实暴露你没想到的传导路径**，这正是推演的价值：预览告诉你写什么，推演告诉你世界因此变成什么样。
