# 04 · 从状态到行动：会活、会算、会行动的对象

> 配套实验：`python scripts/explore.py --step 4` 和 `--step 5`，以及 Web 端「事件流」「球员对象」「决策中心」三个 Tab。

## 知识图谱停在"找"，业务世界要"动"

前三章的世界其实是**静态的**：三元组躺在那里，推理把它展开。但真实业务要问的是另一串问题：德布劳内**现在**体能怎么样？**为什么**是这个状态？**接下来该怎么办**？做了之后**世界会变成什么样**？

这就是"现代本体"和知识图谱的分界线。 业界有一个好记的隐喻：给对象装上五官——

| 器官 | 含义 | 在本项目里的代码 |
|---|---|---|
| 嘴 | 数据入口：世界对对象说话 | `POST /api/events`、`engine/events.py` |
| 鼻子 | 感知：对象知道发生事了 | `PlayerObject.perceive()`（收件箱） |
| 脑子 | 计算：知道"我现在怎么样" | `PlayerObject.compute()`（体能公式） |
| 眼睛 | 权限：谁允许做 | `engine/actions.py` 的前置条件（报名上限） |
| 手 | 行动：能改变世界 | `engine/actions.py` 的 `execute()` |
| 脚 | 运行：这一切有个地方持续发生 | `engine/world.py` 的 `World.dispatch()` |

## 一条事件的完整旅行

在「事件流」Tab 给德布劳内注入一个受伤事件，或者跑 `--step 4`。背后依次发生：

1. **感知**：事件进 `PlayerObject` 的收件箱（`world.py` 的 dispatch 第一步）。
2. **结算**：伤情三元组写入 **effects 层**——"效果即事实"， InjuryEvent 变成 `(p_am1, injuredWith, inj_p_am1)` 和 `(inj_p_am1, weeksOut, 4)`，和手写的数据同级。
3. **重算**：所有对象的 `compute()` 重新跑体能公式 → 写入 **state 层** → OWL-RL 重新物化 → 规则层重新匹配。
4. **传导**：伤情写入后规则层重新匹配——前腰位置可用人数变化会让征调建议出现或消失，体能变化会让轮休建议出现或消失。每个事件的结算过程在传导链里有**中文解释**——`dispatch` 返回的 `chain` 字段已结构化为四段（`perceive` 感知 / `settle` 结算 / `compute` 派生 / `rules` 规则），前端因果链卡片逐段渲染；逐级影响推演（可用人数 → 阵容强度 → 胜率，每步标注公理）是第二期的课题。

关键观念：**状态不是存的，是算的**。`fitness` 从不落库（state 层每次 dispatch 全量重写），改一个出场事实，体能跟着变——这正是第三章"推断不落库"的思想延伸到派生属性。

## 行动要带边界：治理三要素

建议动作也是推论（规则把"情况"映射为"动作"）。但让它直接改世界之前，Palantir 式的写路径有三个约束，`engine/actions.py` 各给了一个：

1. **前置条件**：`CallUpYouth` 受报名名单上限 16 人约束。超编 → 写 `(动作, vetoed, true)` → 规则层不再建议它（否决也是事实）。
2. **审批**：`StartTreatment` 要**两次执行**——第一次登记待审批（"需队医确认"），第二次才是真执行。审批门是动作的属性，不是某个人的临时决定。
3. **审计**：每次事件与执行都写 `kb.audit`（step 计数器、动作、结果、原因）。`GET /api/audit` 随时回看世界为什么变成现在这样。

执行前后还可以**预览影响**：`POST /api/preview-action` 返回将新增/撤销的三元组，不落库——决策之前先推演。

## 效果即事实，闭环合拢

执行「启动治疗」：伤病记录被移除——effects 层的运行时伤病直接删除，声明层伤病走 retractions 撤销（撤销也是写回）→ 重算刷新 → "重伤建议治疗"的条件不再成立 → **建议自动从清单消失**。不需要谁去手动"关闭"这条建议——世界变了，关于世界的推论跟着变。

跑 `--step 5` 看完整闭环：预览 → 审批两步 → 审计日志。

## 回到那张演进图

```
数据存储 → 关系连接 → 语义理解 → 状态计算 → 推理决策 → 行动执行
   (SQL)     (图谱)     (OWL-RL)   (compute)   (规则层)   (actions)
```

知识图谱把张三从表里"放出来"成为对象；现代本体进一步给对象装上嘴、鼻、脑、眼、手、脚。本项目的 2000 行代码，就是这条路线的一块教学沙盘。
