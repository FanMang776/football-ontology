# 01 本体是什么：从一条三元组开始

> 本章配套 `python scripts/explore.py --step 1`。前置条件：`pip install -r requirements.txt`。

## 一条真实的三元组

`ontology/data.ttl` 的第 17 行附近写着这样一段：

```turtle
ex:p_bt01 a ex:PhysicalProduct ; rdfs:label "降噪蓝牙耳机 BT-01"@zh ;
    ex:suppliedBy ex:sup_shengke ; ex:price 899 ; ex:stock 40 ;
    a ex:cat_headphone ;
```

其中 `ex:p_bt01 ex:suppliedBy ex:sup_shengke` 就是本项目的第一条教学三元组：**主语** `p_bt01`（降噪蓝牙耳机 BT-01）、**谓语** `suppliedBy`（由…供应）、**宾语** `sup_shengke`（声科电子）。它陈述了一个事实：这款耳机由声科电子供应。

本体（Ontology）的全部原材料就是这种"主语-谓语-宾语"结构，术语叫**三元组**（triple）。看起来朴素得近乎简陋，但它的表达能力来自两点：

1. **边的宾语可以是另一个节点**，于是三元组连成一张图；
2. **谓语本身也可以被描述**（比如声明 `suppliedBy` 是一个对象属性），于是图的结构自带约束和含义。

## 三元组世界观

把上面的三元组继续铺开，整个业务就成了一张有向标注图：

- `p_bt01 substituteFor p_x2`——BT-01 的替代品是头戴耳机 X2；
- `b_music hasPart p_bt01`——音乐套装包含 BT-01；
- `promo_618 promotes cat_digital_acc`——618 大促推广的是"数码配件"这个**品类**，不是某个具体商品。

关系数据库存储的是"表 + 外键"，面向对象存储的是"对象 + 引用"，而三元组存储的是**带全局词表的谓语**。`suppliedBy`、`hasPart`、`substituteFor` 不是某张表的字段名，而是跨所有实体统一使用的谓语。这意味着"谁供应了什么""什么包含什么""什么替代什么"可以用同一套查询语言（SPARQL）在任意实体之间提问——这是后文所有推理和决策的地基。

## TBox 与 ABox：本体的"语法书"和"事实库"

本项目把知识分成两个文件，正好对应本体工程的两个经典概念：

**TBox（术语框，Terminology box）**——描述"这个世界里有哪些类、哪些关系、它们之间什么关系"，相当于语法书。见 `ontology/schema.ttl`：

```turtle
ex:PhysicalProduct rdfs:subClassOf ex:Product ; rdfs:label "实体商品"@zh .
ex:Bundle   rdfs:subClassOf ex:Product ; rdfs:label "捆绑套装"@zh .
ex:Customer rdfs:subClassOf ex:Party ; rdfs:label "客户"@zh .
```

这三行说：实体商品是一种商品，捆绑套装也是一种商品，客户是一种参与方（`Party`）。它们本身不陈述任何具体事实，只是给事实提供"可判定的句型"。

**ABox（断言框，Assertion box）**——描述"这个世界里实际发生了什么"，相当于事实库。`ontology/data.ttl` 全部是 ABox：

```turtle
ex:sup_shengke a ex:Supplier ; rdfs:label "声科电子"@zh ; ex:status "active" .
ex:o1  a ex:Order ; ex:placedBy ex:c_zhangwei ; ex:orderStatus "pending" ;
    ex:hasLine ex:o1_l1 .
```

声科电子是供应商、订单 o1 由张伟下达——每一条都是具体断言。注意 `a` 是 Turtle 语法里 `rdf:type` 的缩写："声科电子**是**一个 Supplier"。

TBox 与 ABox 分开存放有一个直接的工程好处：改业务规则（调整类层级、给属性加公理）不动数据，改数据不动 schema。第三章会看到，推理机正是拿着 TBox 这本语法书去读 ABox 的事实库，读出白纸黑字之外的含义。

## 三种世界观对比

同一个"商品"概念，在三种数据模型里的处境完全不同：

| 维度 | 关系数据库 | 面向对象 | 本体（RDF/OWL） |
|---|---|---|---|
| 基本单元 | 行（表 + 外键） | 对象（类 + 引用） | 三元组（主语-谓语-宾语） |
| 分类体系 | 枚举字段或字典表 | 单继承为主，编译期固定 | `subClassOf` 图，任意多父，数据即模型 |
| 关系 | 外键，查询时显式 JOIN | 对象引用，方向固定 | 全局谓语，可声明传递/对称/逆 |
| "蓝牙耳机属于数码配件" | 一行字典表数据 | 可能是一个枚举值 | 一条 `subClassOf` 公理，可被推理使用 |
| 新增一种查询 | 写 SQL，可能要改表结构 | 写方法 | 写一条 SPARQL，模型不用动 |

关键差异在倒数两行。关系库里品类是**数据**，"耳机属于数码配件"只是字典表里的一行，数据库对它没有任何理解；本体里品类层级是**公理**，推理机可以利用它得出新结论（比如"BT-01 是电子产品"——尽管数据里从未这么写）。这正是第 02 章的主题。

## 本章动手

```bash
python scripts/explore.py --step 1
```

你会看到（数字来自实际运行）：

```
声明三元组共 390 条。前 25 条：

  Action             label                  "决策动作"@zh
  Action             subClassOf             <http://example.org/ecom#BusinessObject>
  Bundle             label                  "捆绑套装"@zh
  ...
```

390 条就是本项目 ABox + TBox 的全部"白纸黑字"。请扫一遍前 25 条：它们按主语排序，前半段几乎全是 schema.ttl 的类定义——本体项目里，"模型"和"数据"用的居然是同一种存储格式，这一点值得停下来体会。

也可以启动 Web 界面对照着看：`python -m uvicorn api.main:app --reload`，打开 http://127.0.0.1:8000 的「图谱总览」Tab，刚才那些三元组就是图上的节点和边。
