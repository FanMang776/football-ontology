# 01 · 本体是什么：从查表到对象

> 配套实验：`python scripts/explore.py --step 1`

## 从一张表说起

假设你要回答一个问题：**范戴克效力于哪家俱乐部？**

关系数据库里，答案藏在两张表里。球员表里有一行"范戴克"，带一个 `club_id` 外键；你要拿着这个 id 去俱乐部表里再查一次。问题变成"范戴克的俱乐部的合同还剩几年"，就要再 join 一张合同表。问题再变成"和范戴克同位置的球员都有谁的合同快到期"——join 的层数和问题的复杂度一起爆炸。

关系数据库擅长把数据**整整齐齐放进桶里**。但当你最关心的是"谁和谁有什么关系"时，你就要不停搬表、找表、拼表。

## 本体的做法：让对象自己带着关系

本体不把数据按"表"组织，而是按**对象**组织。在 `ontology/data.ttl` 里，范戴克是这样的：

```turtle
ex:p_cb1 a ex:Player, ex:CentreBack ; rdfs:label "范戴克"@zh ;
    ex:playsFor ex:club_star ;
    ex:hasContract ex:c_cb1 ;
    ex:participatesIn ex:m_d1, ex:m_d2 ; ex:minutesPlayed 75, 60 .
```

每一行都是一条**三元组**：主语、谓语、宾语。

- `ex:p_cb1 ex:playsFor ex:club_star` —— 范戴克 **效力于** 群星 FC
- `ex:p_cb1 ex:hasContract ex:c_cb1` —— 范戴克 **拥有合同** c_cb1

关系不再是"某张表里的一列"，而是对象与对象之间**有名字的边**。问"范戴克的合同剩几年"，就是沿着 `hasContract` 这条边走一步，再看合同节点上的 `contractYears`——不用在别的表里把他挨个认一遍。

## 跑一下

```bash
python scripts/explore.py --step 1
```

你会看到 312 条声明三元组的抽样。注意几个细节：

1. **位置是类型，不是字段**。范戴克的第一行是 `a ex:Player, ex:CentreBack`——他"是"中后卫这个类的一员，而不是有一个"位置"字符串字段。这个区别是第三章推理的伏笔。
2. **label 只是展示名**。`rdfs:label "范戴克"@zh` 给节点一个中文名，机器用的是 `p_cb1` 这个 id。
3. **本文件只有"白纸黑字的事实"**。谁效力谁、踢了几分钟、伤停几周——都是写死的。至于"德布劳内算不算过度使用"，这里一个字都没有，那是推理和规则的事（第三章、第四章）。
